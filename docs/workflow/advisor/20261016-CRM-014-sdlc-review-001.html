Ranked findings

  1. Product assumptions passed every review. High confidence. Story AC04, UX AC04, and sealed tests specified Teachers > System Logs. The human later clarified that Teachers and Logs are peers. This is an upstream contract error, rather than evidence of worker disobedience. The joint review confirmed the approved hierarchy, but did not challenge its product meaning. Separator spacing also required human correction after review. Evidence: story, UX assessment, and manual feedback. Alternative explanation: the final feedback also refined an earlier approved requirement. The evidence cannot establish when the human first rejected that assumption.

  2. The process exceeded the feature's needs. High confidence for observed friction, medium confidence for its causes. The human could not isolate Gate 1 from about 3,100 lines of workspace changes. The human twice challenged architecture complexity. The plan then shrank from 317 to 106 lines. Later, the human requested a shorter GREEN/RED summary and direct small corrections. The final ledger is 7,737,271 bytes because it retains extensive approval evidence. Evidence: chat turns 01a13965, 01a13a50, 01a13a51, 01a13ffa, and the ledger summary. Some friction came from this being a pipeline dry run. A mature run might need less setup work.

  3. Exact runtime preparation was checked too late. High confidence. A 158.446-second worker completed before the source scanner rejected ee-crm/node_modules/.bin/baseline-browser-mapping. The later setup recovery reproduced that scan in about 0.2 seconds and supplied a compatible mounted runtime without Factory changes. The requested workflow model was also unavailable and needed explicit substitution. Evidence: setup recovery, run 001, and model evidence. This does not justify weaker source integrity checks or a general runtime rewrite.

  4. A failing feature check did not isolate the feature. High confidence. A08 required the entire document to fit at 320px. The original baseline already overflowed. A08 failed twice despite breadcrumb changes. Independent QA then tested component containment and added document overflow. Five deliberately broken breadcrumb layouts failed the revised checks. Run 003 then passed without further source changes. Evidence: QA addendum, comparison, and run 002 attempts. The second attempt consumed 142.644 worker seconds and 1,573,156 reported input tokens. It did not resolve A08. Earlier baseline diagnosis might have avoided that attempt. This is a counterfactual, not a measured saving.

  5. Delivery authority and gate completion need separate states. High confidence. Final source corrections invalidated the gate snapshots. The human then explicitly authorized commit, merge, and push. Delivery completed at 66fc815. The release record correctly states that no new full Factory run or joint review occurred. However, the ledger says COMPLETED while requirements are PENDING, other gates are NOT_STARTED, and five wizard results remain pending. Evidence: release decision, final state, and manual results. The user authorized delivery. The issue is truthful workflow classification, not missing user authority.

The isolation, immutable controls, retained failed runs, baseline comparison, independent QA correction, and final source-to-commit checks were useful. The proposals retain these controls. The evidence does not support replacing the worker model or increasing attempt budgets.

Lightweight bug and spike flows

Small bug flow: The developer records the symptom and affected criterion. QA reproduces the failure at the public UI or module interface. The developer diagnoses the cause and applies the smallest authorized correction. QA runs the focused regression and relevant preserved journeys. An independent reviewer checks the delta. The runner presents final source identity, human feedback, limits, and the release decision. A product hierarchy change first returns to the requirement owner. The bug flow does not waive an existing factory story's gates.

Workflow spike: The workflow maintainer tests P6 in an isolated ledger fixture. The question is whether explicit correction delivery can remain auditable without false gate completion. The budget is 60 minutes and zero worker inference turns. Evidence must cover invalidated gates, pending human checks, final source changes, and explicit delivery authorization. Stop when these states are represented consistently or the budget ends. Return a workflow proposal, not a production release.
