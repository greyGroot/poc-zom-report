## Ranked findings

1. **Product assumptions passed every review. High confidence.** Story AC04, UX AC04, and sealed tests specified `Teachers > System Logs`.
   The human later clarified that Teachers and Logs are peers. This is an upstream contract error, rather than evidence of worker disobedience.
   The joint review confirmed the approved hierarchy, but did not challenge its product meaning.
   Separator spacing also required human correction after review.
   Evidence: [story](../../stories/CRM-014-add-breadcrumb-navigation.md), [UX assessment](../../../.sdlc/CRM-014/review-001/ux/assessment.md), and [manual feedback](../../../.sdlc/CRM-014/revision-004/human-feedback.json).
   Alternative explanation: the final feedback also refined an earlier approved requirement. The evidence cannot establish when the human first rejected that assumption.

2. **The process exceeded the feature's needs. High confidence for observed friction, medium confidence for its causes.**
   The human could not isolate Gate 1 from about 3,100 lines of workspace changes. The human twice challenged architecture complexity.
   The plan then shrank from 317 to 106 lines. Later, the human requested a shorter GREEN/RED summary and direct small corrections.
   The final ledger is 7,737,271 bytes because it retains extensive approval evidence.
   Evidence: chat turns `01a13965`, `01a13a50`, `01a13a51`, `01a13ffa`, and the ledger summary.
   Some friction came from this being a pipeline dry run. A mature run might need less setup work.

3. **Exact runtime preparation was checked too late. High confidence.**
   A 158.446-second worker completed before the source scanner rejected `ee-crm/node_modules/.bin/baseline-browser-mapping`.
   The later setup recovery reproduced that scan in about 0.2 seconds and supplied a compatible mounted runtime without Factory changes.
   The requested workflow model was also unavailable and needed explicit substitution.
   Evidence: [setup recovery](../../architecture/CRM-014-setup-recovery-001.md), run 001, and [model evidence](../../../.sdlc/CRM-014/operator-003/model-support-summary.json).
   This does not justify weaker source integrity checks or a general runtime rewrite.

4. **A failing feature check did not isolate the feature. High confidence.**
   A08 required the entire document to fit at 320px. The original baseline already overflowed.
   A08 failed twice despite breadcrumb changes. Independent QA then tested component containment and added document overflow.
   Five deliberately broken breadcrumb layouts failed the revised checks. Run 003 then passed without further source changes.
   Evidence: [QA addendum](../../../.sdlc/CRM-014/verification-003/test-impact-addendum.md), [comparison](../../../.sdlc/CRM-014/execution-002/mobile-comparison.json), and run 002 attempts.
   The second attempt consumed 142.644 worker seconds and 1,573,156 reported input tokens. It did not resolve A08.
   Earlier baseline diagnosis might have avoided that attempt. This is a counterfactual, not a measured saving.

5. **Delivery authority and gate completion need separate states. High confidence.**
   Final source corrections invalidated the gate snapshots. The human then explicitly authorized commit, merge, and push.
   Delivery completed at `66fc815`. The release record correctly states that no new full Factory run or joint review occurred.
   However, the ledger says `COMPLETED` while requirements are `PENDING`, other gates are `NOT_STARTED`, and five wizard results remain pending.
   Evidence: [release decision](../../../.sdlc/CRM-014/closure-001/release-decision.json), [final state](../../../.sdlc/advisor/20261016-CRM-014-sdlc-review-001/final-state-summary.json), and [manual results](../../../.sdlc/CRM-014/manual-test-results.json).
   The user authorized delivery. The issue is truthful workflow classification, not missing user authority.

The isolation, immutable controls, retained failed runs, baseline comparison, independent QA correction, and final source-to-commit checks were useful.
The proposals retain these controls. The evidence does not support replacing the worker model or increasing attempt budgets.

## Bounded improvement proposals

These proposals are not implemented. Each experiment changes one main variable and preserves the original evidence.
Budgets below are proposed limits, not runtime configuration or approval.

### P1. Add a product hierarchy table before detailed planning

**Target:** `.agents/skills/f-ba/SKILL.md`, with a consistency check in `f-ux` and `f-review`.
**Proposed instruction:** “Record each affected page, its parent, and its breadcrumb. Mark top-level pages explicitly. Ask the human to resolve unsupported hierarchy assumptions.”

For this story, the corrected table is:

| Page | Parent | Breadcrumb |
| --- | --- | --- |
| Teachers | None | None |
| System Logs | None | None |
| Teacher schedule | Teachers | Teachers → teacher |
| Teacher day | Teacher schedule | Teachers → teacher → day |

**Owner:** BA owns the table. UX checks page meaning and visible states. The implementation reviewer challenges one unsupported product assumption.
**Experiment:** Apply the table to the next navigation story before producing detailed diagrams. Budget: 20 minutes, zero paid worker runs.
**Success:** Every affected route has an explicit parent. No reviewer infers parenthood from a home link or navbar position.
**Stop:** Return an unresolved hierarchy to Gate 1. Do not author acceptance assertions for an unresolved assumption.
**Approval:** Human approves product meaning at Gate 1 and rendered hierarchy at Gate 2. Later changes follow affected gates.
**Missing evidence:** One story cannot establish a general rate of hierarchy errors.

### P2. Make each gate review small and specific

**Target:** `.agents/skills/f-orchestrator/SKILL.md`, its gate presentation template, and `f-architect` deliverables.
**Proposed format:** “Decision. Changed behavior. Preserved behavior. Checks and blockers. Links to the current gate diff and full evidence.”
Limit the default card to 150 words. Give a path-filtered diff against the last presented snapshot.
Use one short architecture plan for local UI changes. Record N/A for irrelevant data or deployment sections.
Treat visual before/after artifacts as compact views of the same decision, rather than separate essays.

**Owner:** Workflow maintainer and Orchestrator. Architect owns the shorter plan.
**Experiment:** Use this presentation on one small story. Budget: one template revision, 45 minutes, zero worker runs.
**Success:** Every card links an isolated diff. The reviewer can identify the exact changed behavior without opening unrelated work.
Record requests for clarification. Compare them with this run's observed review complaints, without claiming a time saving.
**Stop:** Retain required evidence and gate criteria. Do not shorten cards by hiding blockers or unresolved decisions.
**Approval:** The human approves the workflow template change. All seven gates remain in the next factory feature unless explicitly revised.

### P3. Move exact runtime checks before paid dispatch

**Target:** `.agents/skills/f-operator/SKILL.md` and its provision/dispatch readiness procedure.
**Precise change:** Run the actual candidate manifest scan in the provisioned layout. Start the sealed evaluator through its real mount boundary.
Check empty host mount points, read-only dependencies, private generated output, protected writes, and cleanup.
Record the available executable, model, and reasoning configuration. Distinguish local configuration checks from successful provider inference.
Reuse the proven mounted setup when its fingerprints match. Do not create a new sandbox design for every story.

**Owner:** Operator. Architect owns a new runtime design only when the existing layout fails.
**Experiment:** Repeat readiness against one nested-app fixture before the next dispatch. Budget: 30 minutes, zero inference turns.
**Success:** The original symlink incompatibility fails readiness before a worker starts. The mounted layout passes source and evaluator startup checks.
**Stop:** Any source identity mismatch, protected-write success, or incomplete cleanup blocks readiness.
**Approval:** QA reviews changed evaluator setup at Gate 4. Operator presents exact runtime and control identity at Gate 5.
**Missing evidence:** A model catalog entry does not prove inference entitlement. A paid smoke requires explicit inclusion in the approved budget.

Use deliberate component mutations to show that a revised assertion still detects real defects.

**Owner:** Verificator.

**Stop:** Stop if the change removes intended coverage or the baseline state cannot be reproduced.
**Approval:** Renew Gate 4 for changed assertions. Package a new immutable control and renew Gate 5 before delivery execution.

### P5. Diagnose before another paid attempt

**Target:** Factory retry policy and `.agents/skills/f-operator/recovery.md`.
**Precise change:** First-failure output must identify the producer, baseline behavior, scope, and repairability before another worker receives it.
For the next uncertain infrastructure/UI cohort, propose `task.budget.maxAttempts: 1`. Diagnose once before approving a second run.
The current CLI does not offer an advisor-side pause between automatic attempts. Do not imply that a prompt can enforce one.

**Owner:** Operator owns failure triage. Factory maintainer owns any future automatic failure classifier.
**Experiment:** Use a one-attempt task budget for one small story with uncertain setup. Allow one diagnostic cycle, up to 30 minutes.
Permit a second worker only through a separately approved run after diagnosis.
**Success:** An unchanged baseline defect or deterministic setup failure receives no automatic second paid attempt.
**Stop:** Return to the human if repairability remains unknown. Do not increase the budget to conceal uncertainty.
**Approval:** Gate 5 explicitly approves the one-attempt budget. A later run requires renewed dispatch approval.
**Tradeoff:** This can add a human pause for a genuine easy code defect. Compare that cost before adopting the policy broadly.

### P6. Define a small-correction path and truthful completion states

**Target:** `docs/workflow/post-green-review.md`, `.agents/skills/f-runner/session.md`, and the State Ledger contract.

Any evaluation-only option must use a supported, separately approved manual evaluator path. The CLI currently supports `--agent manual`.
Label that result as manual evaluation. Do not count it as a worker success or silently reuse the old 95-case contract.

**Owner:** Workflow maintainer owns the contract. Orchestrator owns transitions. QA owns revised assertions. Runner owns final identity and human feedback.
**Experiment:** Replay this story's final correction in a read-only state fixture. Budget: 60 minutes, zero worker runs, no release action.
**Success:** The fixture records explicit delivery authorization, pending manual checks, superseded AC04, and final verification without contradictory gate-completion claims.
**Stop:** Stop if the path grants automatic release, bypasses independent QA, hides stale evidence, or broadens application scope.

## Lightweight bug and spike flows

**Small bug flow:** The developer records the symptom and affected criterion. QA reproduces the failure at the public UI or module interface.
The developer diagnoses the cause and applies the smallest authorized correction. QA runs the focused regression and relevant preserved journeys.
An independent reviewer checks the delta. The runner presents final source identity, human feedback, limits, and the release decision.
A product hierarchy change first returns to the requirement owner. The bug flow does not waive an existing factory story's gates.

**Workflow spike:** The workflow maintainer tests P6 in an isolated ledger fixture. The question is whether explicit correction delivery can remain auditable without false gate completion.
The budget is 60 minutes and zero worker inference turns. Evidence must cover invalidated gates, pending human checks, final source changes, and explicit delivery authorization.
Stop when these states are represented consistently or the budget ends. Return a workflow proposal, not a production release.
