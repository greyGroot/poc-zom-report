# 🧪 Інструкція з тестування (TESTING_GUIDE.md)

Цей документ описує покроковий процес тестування функціоналу телеметрії: від локальних тестів до перевірки реальної зустрічі в Zoom.

---

## Крок 1. Локальна перевірка бекенду та логіки телеметрії

Перед деплоєм переконайтеся, що всі автоматизовані тести проходять локально:

```bash
# 1. Запуск повного набору тестів телеметрії (69 перевірок)
npm run test:telemetry

# 2. Перевірка зворотньої сумісності класичного Reports API
npm test
```

> **Очікуваний результат:** обидва тести завершуються повідомленням `ALL TESTS PASSED!` з кодом виходу `0`.

## Крок 2. Тестування валідації вебхука в Zoom Marketplace (CRC Challenge)

Після деплою на Vercel та налаштування змінної `ZOOM_WEBHOOK_SECRET_TOKEN`:

1. Перейдіть у [Zoom App Marketplace](https://marketplace.zoom.us/) -> ваше **Server-to-Server OAuth** додаток.
2. Відкрийте розділ **Feature** -> **Event Subscriptions**.
3. У полі **Event notification endpoint URL** вкажіть:
   ```text
   https://<ваш-домен-vercel>.vercel.app/api/webhooks/zoom
   ```
4. Натисніть кнопку **Validate**.

### Що відбувається під капотом:
- Zoom надсилає POST-запит з `payload.plainToken`.
- Наш бекенд у `api/webhooks/zoom.js` розраховує HMAC-SHA256 хеш з вашим `ZOOM_WEBHOOK_SECRET_TOKEN`.
- Повертає статус 200 та `{ plainToken, encryptedToken }`.
- Zoom відображає зелену позначку **"Validated"**.

## Крок 3. Тестування реальної зустрічі в Zoom (End-to-End)

Для перевірки реального потоку подій проведіть тестове заняття:

1. **Організатор:** Увійдіть у Zoom з тестового акаунту `gray.rsm@gmail.com` (Sergii Rumyantsev).
2. **Старт уроку:** Запустіть миттєву або заплановану зустріч.
   - *У Redis буде зафіксовано подію `meeting.started`, статус зустрічі стане `live` (зелений бейдж «🟢 В ефірі»).*
3. **Підключення учня:** Підключіть другого учасника (зі смартфона, вкладки інкогніто або іншого пристрою).
   - *Вебхук `meeting.participant_joined` зафіксує ім'я, системний ID, IP-адресу та точний час входу.*
4. **Імітація заняття:**
   - **Сценарій А (VERIFIED):** Залишайтеся в зустрічі разом більше 30 хвилин.
   - **Сценарій Б (ONLY_HOST):** Учень виходить або не приходить, викладач чекає 15 хвилин сам.
   - **Сценарій В (SHORT_CALL):** Тестовий дзвінок тривалістю менше 10–15 хвилин.
5. **Завершення уроку:** Викладач натискає **«Завершити зустріч для всіх»**.
   - *Вебхук `meeting.ended` оновить тривалість, розрахує business_status та запустить спробу підтягнути QoS з graceful fallback при 403.*

## Крок 4. Перевірка результатів у веб-інтерфейсі

1. Відкрийте веб-сторінку вашого проєкту:
   ```text
   https://<ваш-домен-vercel>.vercel.app/#telemetry
   ```
   *(або відкрийте вкладку **«⚡ Live Webhooks Telemetry»**).*
2. **Перевірте відображення картки уроку:**
   - **Викладач:** відображається Sergii Rumyantsev (`gray.rsm@gmail.com`).
   - **Статус зустрічі:** «Завершено» (або «🟢 В ефірі», якщо урок ще триває).
   - **Час:** точний час початку, завершення та загальна тривалість за Києвом.
   - **Статус уроку:** правильний кольоровий бейдж:
     - `VERIFIED (≥30хв)` — зелений.
     - `ТІЛЬКИ ВИКЛАДАЧ (≥15хв)` — жовтий.
     - `КОРОТКИЙ ДЗВІНОК` — червоний.
3. **Розгорніть блок учасників (клік на рядок або кнопку «👥 учасник(ів)»):**
   - Перевірте наявність бейджа **«Викладач (Організатор)»** та **«Студент»**.
   - Перевірте відображення IP-адреси, сесійних інтервалів (час входу – час виходу) та точного часу на уроці.
4. **Тест автооновлення:**
   - Увімкніть чекбокс **«Авто (10с)»**.
   - Спостерігайте за лічильником зворотного відліку `10с... 1с`. Дані оновлюються автоматично без перезавантаження сторінки.
